# 하네스 규칙 변경 기록

새 항목은 맨 위에 써요. `/sonic-harness-be:update`가 이 기록과 git 로그로 무엇이 바뀌었는지 보여 줘요.

- 2026-10-25: Swagger 에러 응답과 예시. 모든 에러 응답이 `ProblemDetailsDto`(RFC 9457) 스키마와 코드별 예시로 나와요. 400(`VALIDATION_FAILED`, 숫자 path `HTTP_400`)·401(`@Public()` 아니면)·403(`@Roles()`)은 `createOpenApiDocument`가 자동으로 붙이고, 비즈니스 예외는 handler에 `@ApiErrors(예외 클래스...)`로 적어요(`common/exceptions/api-errors.ts`). 예외 클래스는 `static readonly code·status·example`을 둬요(sample-item·공통 코드 템플릿 반영). `@Public()` API는 Swagger에서 `security: []`라 자물쇠가 없어요. lint: controller가 같은 feature exception을, exception이 다른 feature `index.ts`(예외 다시 내보내기)를 가져올 수 있어요. Spectral: path 파라미터가 있는 API에 404가 없으면 경고. 이미 적용한 프로젝트는 update 뒤 `app.setup.ts`·`auth.decorators.ts`를 템플릿과 합치고, 예외 클래스에 static 값을 더하고 `npm run openapi`로 다시 만들어요 (0.4.0)
- 2026-10-25: 평가 결과 보완. `test`·`test:cov`에 `--passWithNoTests`(공통 코드 N이면 단위 테스트가 0개예요). 로그인 사용자는 `@CurrentUser() user: AuthUser`로 받아요(`AuthRequest`는 `roles.ts`로 옮겼어요). `@Transactional()` service 단위 테스트 도우미 `test/setup/transactional.ts`(`noOpTransactionalModule`, `runInCls`). 평가 `run.sh`가 feature 명령(`node harness.mjs`)을 쓸 수 있어요 (0.3.1)
- 2026-10-25: 평가. `evals/setup-sandbox.sh`, `hook-check.sh`, `init-check.sh [y|n]`, `run.sh`와 기준 작업 5개(상품 CRUD·권한, 주문 트랜잭션·feature 경계, 공통 코드 필드, 옵션 통합 API, 파일 업로드), `checklist.md`(자동 10개·수동 6개 + 작업별). `run.sh`는 평가용 Postgres를 띄우고, 결과 코드를 커밋 대신 `.patch`로 남겨요
- 2026-10-25: CI. `templates/.github/workflows/ci.yml`(job: lint·test·e2e·openapi·migration·security), Dependabot, `scripts/openapi.mjs`(DB 없이 preview 모드로 `openapi.json` 생성·비교), `scripts/harness-checks.mjs`(env 키, controller별 e2e, 새 패키지 이유), `.dependency-cruiser.cjs`(컴파일 결과 기준 순환 검사), `spectral.yaml`(경로 kebab-case, DELETE 204, POST 201). npm audit은 운영 의존성 critical만 막아요. init은 프로젝트 tsconfig에도 `paths`를 적고(dependency-cruiser가 `${configDir}`를 못 읽어요), `nest new` README를 바꾸고(예시 토큰이 gitleaks 오탐), branch protection 명령을 안내해요. feature 뼈대와 명령에 엔드포인트별 권한 안내. hook은 node_modules 실행 파일만 쓰고 `..` 경로를 건너뛰어요. `app.setup.ts`가 `VERSIONING`을 export해요. JWT: 알고리즘 HS256 고정, 발급 토큰에 만료(`JWT_EXPIRES_IN_SECONDS`, 기본 3600), exp 없는 토큰 거부(e2e로 확인) (0.3.0)
- 2026-10-25: 플러그인 명령 6개(init·status·update·check·contribute·feature)와 hook. init은 `nest new` 시작 파일(main·app.module·vitest 설정)을 템플릿으로 바꾸고 예시 파일·oxlint·`.prettierrc`를 지워요. deps는 major를 고정해 설치하고 scripts·nest-cli Swagger 플러그인을 설정해요(`migration:run`·`revert`는 먼저 빌드해요). `common-codes`는 공통 코드 템플릿을 넣고 migration 이름을 지금 시각으로 바꿔요. `feature <이름>`은 sample-item 뼈대를 이름만 바꿔 만들고 app.module에 등록해요. hook: 경로 kebab-case(migration 제외), 저장 후 format·lint, Stop에서 typecheck·관련 단위 테스트. `.gitignore` 템플릿 추가(`nest new --skip-git`은 만들지 않아요) (0.2.0)
- 2026-10-25: 템플릿과 harness.md. Nest 12 기본(ESM, Vitest)에 맞춰 테스트 규칙을 Jest에서 Vitest로 바꾸고 import에 `.js`를 붙여요. `templates/`(main·app.setup·전역 필터 RFC 9457·JWT 전역 guard·Roles·nestjs-pino·request ID·throttler·helmet·health·zod env·data-source·Testcontainers e2e·라우트 전체 401 테스트·MSW), `templates.feature/`(sample-item 뼈대: TransactionHost repository, service 단위 테스트, CRUD e2e), `templates.common-codes/`(그룹·코드 entity, 캐시, `@IsCommonCode`·`@NotCommonCode`, 관리 API, seed migration). migration은 빌드에 포함되도록 `src/infra/database/migrations/`에 두고 lint에서 빼요. module이 같은 feature constants를, service가 같은 feature service를 가져올 수 있어요
- 2026-10-25: lint 규칙. Feature·Layer 경계(boundaries: 접미사별 레이어, 다른 feature는 index.ts로만, compositions는 조합만), import 제한(TypeORM 위치, HTTP 예외는 controller·common, forwardRef 금지), 매직 넘버, disable 주석 이유 필수, 해요체 테스트 이름. 로컬 규칙 18개(`eslint-plugin-sonic-be.mjs`): DI·DTO·응답 DTO·예외·TypeORM(take, raw SQL, synchronize, eager/lazy, timestamptz)·트랜잭션(warn)·N+1·업로드·공통 코드·통합 API(warn). 샘플은 `npm run test:lint`
- 2026-10-25: 첫 뼈대. Prettier·commitlint는 FE 하네스와 같아요. tsconfig는 데코레이터 메타데이터를 켜고 `verbatimModuleSyntax`·`exactOptionalPropertyTypes`를 꺼요. ESLint는 TypeScript 공통 규칙만 있고, `consistent-type-imports`는 Nest DI를 깨서 쓰지 않아요 (0.1.0)
